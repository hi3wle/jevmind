# Solo execution

Read applicable repository instructions and the original request. Identify the target repository, dirty baseline, acceptance criteria, required checks/reviews and permissions. Keep one implementation owner. If the task belongs to an AI DevKit feature, read its five phase documents and resume the existing planning checklist. Existing project workflow remains authoritative.

Record mode solo, intended scope, protected behavior, unresolved material decisions and next action in the existing plan when useful. An unresolved business requirement goes to the developer. Model confidence cannot waive required review. Select the smallest feasible change and implement it in this session.

Run affected checks and retain actual command, exit status, source identity and material environment details in testing. Compare with baseline failures without resetting developer work. For routine A, native tracking plus rerunning affected checks after changes is sufficient. If external changes or revision uncertainty invalidate checks, re-ground and rerun them.

On disconnect or quota exhaustion preserve session/work. Establish worker liveness before launching anything. Resume the exact session and read current source, user requirements and plan. If another party edited the source, pause writes to that area and reconcile before continuing.

Update implementation notes, plan status and next step. Report changed behavior, actual checks, current required review and unresolved limitations using the completion policy in AGENTS.md. Record user acceptance only when observed. Keep missing native resource evidence unknown. Use native local evidence where available.

Mode B/C requests need the separately authorized review/collaboration path. If that path is unavailable, report the limitation and required review gate. A request to resume an existing task continues its existing owner.
